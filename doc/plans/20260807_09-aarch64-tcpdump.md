# Plan: Add the AArch64 tcpdump Recipe and Binary

## Summary

Add tcpdump 4.99.4 with libpcap 1.10.4 as a reproducible static AArch64
executable. Port the established tcpdump recipe without changing its source,
feature, license, or smoke-test policy, and consume the existing immutable
AArch64 builder.

Execute this plan after the ARMv7 artifact plans and before the x86-64
builder expansion and GDB plans.

## Problem

tcpdump is the only current utility missing from AArch64. The repository
already distributes the same tool and feature profile for ARMv7 and x86-64,
but it has no AArch64 recipe owner, artifact, catalog row, or assurance record.

## Scope

In scope:

- Add `recipes/tcpdump/aarch64/` with exact copies of the reviewed tcpdump and
  libpcap sources, PGP evidence, licenses, link inventory, and deterministic
  smoke fixture.
- Adapt only the architecture boundary to `linux/arm64`, the AArch64 compiler
  triplet, archive paths, and ELF checks.
- Build and commit `artifacts/aarch64/tcpdump` plus its catalog, checksum,
  README, and TRUST records.

Out of scope:

- Updating tcpdump or libpcap, changing the existing feature omissions, or
  adding privileged live capture to the smoke test.
- Changing the AArch64 builder or either existing tcpdump recipe.
- Adding independent rebuild or attestation claims without qualifying evidence.

## Design

Port `recipes/tcpdump/armv7/` and cross-check it against the x86-64 owner.
Retain tcpdump 4.99.4, libpcap 1.10.4, their tracked archives, detached
signatures, minimal keyring, exact signer fingerprint, license texts, static
configure flags, final-link reconciliation, BPF compilation, and deterministic
offline packet decode. The copied source and authentication files must be
byte-identical to an existing validated owner.

Use the committed AArch64 builder digest and the existing Buildx-only host
flow. Validate a temporary stripped ELF64 little-endian AArch64 `ET_EXEC` with
no interpreter or `DT_NEEDED`, then run the exact version/BPF/decode smoke test
under `linux/arm64` before replacing the artifact. Recheck the installed file
and require its bytes to equal the candidate.

## Affected Components

- `recipes/tcpdump/aarch64/`: add the complete architecture-owned recipe,
  authenticated inputs, notices, link inventory, and smoke test.
- `artifacts/aarch64/tcpdump`: add the validated executable.
- `recipes/catalog.tsv`: enable the `(tcpdump, aarch64)` identity.
- `artifacts/SHA256SUMS`: add the exact sorted checksum.
- `README.md`: list the artifact and one-command rebuild while preserving the
  current table shape until the final presentation plan.
- `TRUST.md`: record source authentication, committed recipe validation, and
  `None` for independent evidence without obscuring the passed recipe checks.

## Implementation Sequence

1. Snapshot the existing tcpdump source/evidence bytes and AArch64 artifact
   hashes, then copy the closest recipe owner.
2. Adapt only platform, triplet, archive paths, ELF assertions, and messages;
   run syntax and offline source validation before compilation.
3. Build once through `./build.sh tcpdump aarch64`, retain the BuildKit cache,
   and require link inventory plus the deterministic target smoke test.
4. Add the artifact and shared live records, run focused and repository
   validation, then commit and push only explicit paths.

## Validation

- Run shell syntax checks, `python3 scripts/recipes.py validate`,
  `git diff --check`, and `./validate.sh`.
- Byte-compare both archives, signatures, keyring, smoke fixture, and reviewed
  license texts with an existing validated tcpdump owner.
- Run `./build.sh tcpdump aarch64` once and require exact source signatures,
  complete link inventory, exact versions, BPF compilation, and deterministic
  offline decode.
- Inspect the candidate and installed artifact with `file`, `readelf`, and
  `sha256sum`; require ELF64 little-endian AArch64 `ET_EXEC`, stripping, no
  interpreter, no `DT_NEEDED`, and candidate/install byte equality.

## Success Criteria

- A fresh checkout rebuilds the committed AArch64 tcpdump from tracked,
  authenticated inputs and the immutable AArch64 builder.
- The artifact passes static ELF, version, BPF, and packet-decode checks on its
  target architecture.
- Existing tcpdump recipes, artifacts, feature policy, and independent evidence
  remain unchanged.
