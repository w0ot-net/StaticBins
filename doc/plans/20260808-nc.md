# Plan: Add GNU nc Across Ready Architectures

## Summary

Add a standalone `nc` artifact built from the signed GNU Netcat 0.7.1 release
for every ready architecture: `aarch64`, `armv7`, `x86`, and `x86_64`. Keep
this rollout independent of BusyBox and socat, use only the locked reusable
builders, and publish the four artifacts in one atomic repository change.

## Problem

The repository has socat, but it does not provide the compact and widely used
`nc` command-line interface. BusyBox can contain an `nc` applet, but using a
multi-call alias as the standalone artifact would couple two otherwise
independent utilities and obscure which implementation and option set users
receive.

GNU Netcat is a real standalone implementation with a small static dependency
surface and an upstream-signed release. Its latest release is old and remains
described upstream as beta software, so the recipe must state its exact limits
and test the supported TCP and UDP behavior rather than imply compatibility
with OpenBSD nc or Nmap Ncat.

## Scope

In scope:

- Add GNU Netcat 0.7.1 as `artifacts/<architecture>/nc` for all four ready
  architectures.
- Authenticate the release with its detached upstream signature and a tracked
  minimal keyring pinned to fingerprint
  `6247640C1C901EE4D800E4E22D583DF1B2D79FC1`.
- Apply one narrowly scoped, checksum-locked local patch that corrects the two
  Linux `IP_PKTINFO` address-copy lengths diagnosed as out-of-bounds by modern
  compilers, and exercise that path with a UDP smoke test.
- Build without NLS, strip the result, validate a classic static `ET_EXEC`, and
  test numeric IPv4 TCP and UDP loopback transfer on the target architecture.
- Document the GNU-specific syntax, IPv4-only scope, enabled execution/tunnel
  features, old upstream status, and legacy signature strength.

Out of scope:

- OpenBSD nc, netcat-traditional, Nmap Ncat, TLS, proxy protocols, Unix-domain
  sockets, or IPv6 support.
- Replacing `socat`, satisfying `nc` through `busybox nc`, or changing the
  BusyBox plan's applet selection.
- Repairing every open GNU Netcat issue or claiming general compatibility with
  another netcat implementation.
- Builder publication, dependency changes, generic recipe abstractions, root
  README changes, or architecture-contract changes.

## Design

Use the official HTTPS release archive
`netcat-0.7.1.tar.gz`, whose accepted SHA-256 is
`30719c9a4ffbcf15676b8f528233ccc54ee6cba96cb4590975f5fd60c68a066f`.
Track the archive, detached signature, and an export-minimal GNU Netcat
keyring under each architecture recipe's `sources/` directory. Declare `pgp`
in each `source.lock`; normal builds verify the checksum and signature using
only those tracked bytes. The signature is valid for the release and key, but
uses DSA with SHA-1 and the key is now expired. Record that limitation in
`TRUST.md` rather than presenting all accepted signatures as equally strong.

Keep the address-copy fix in `patches/` beside the build. The patch changes
only the two copies from `sockaddr_in.sin_addr` in `core_udp_listen()` to use
the size of the address member instead of the containing socket-address
structure. Give the patch a locked SHA-256, apply it with exact context, and
fail if it no longer applies. Document that it is a repository-reviewed local
correctness fix, not separately authenticated upstream code.

Configure with `--disable-nls`, compile only the `netcat` program, and export
it as `/nc`. Use `-O2 -pipe` on all architectures plus
`-march=i686 -msse2 -mfpmath=sse` on x86. Link with `-static` and a linker map,
without `-no-pie`, and require the selected classic static `ET_EXEC` profile.
If a locked builder no longer produces that profile from these flags, stop and
revise the recipe rather than accepting either ELF type opportunistically.

Each architecture owns its source, patch, configure, license, link-map, and
smoke logic. Inventory every final linked archive and match builder-owned
archives to their locked Alpine package versions and reviewed licenses. The
GNU Netcat program is GPL-2.0-or-later; retain its upstream copyright and
applicable source/documentation notices because the complete source archive is
also distributed in the recipe.

The target smoke test runs in an isolated container network namespace. It
checks exact `--version` output, starts the candidate as a numeric IPv4 TCP
listener and client, and compares a unique payload byte-for-byte. It then does
the same for one UDP datagram, using explicit waits, timeouts, cleanup, and a
fixed high port inside the isolated namespace. This verifies startup, socket
creation, listen/connect behavior, EOF handling, the patched packet-info path,
and data transfer without DNS, `/etc/services`, or external connectivity.

The host entry point follows the current candidate-first pattern: check Docker
Buildx before pulls or emulation, consume the exact builder digest, export to a
narrow temporary directory, run host ELF checks and target smoke tests, and
replace `artifacts/<architecture>/nc` only after all checks pass. The installed
file must hash-identically to the validated candidate.

## Affected Components

- `recipes/nc/{aarch64,armv7,x86,x86_64}/`: add Dockerfiles, host and guest
  build scripts, smoke tests, READMEs, source locks, tracked release/signature/
  key inputs, the address-copy patch, and license/link-provenance inventories.
- `recipes/catalog.tsv`: add four enabled `nc` rows, one per ready architecture.
- `artifacts/{aarch64,armv7,x86,x86_64}/nc`: add the four validated stripped
  executables.
- `artifacts/SHA256SUMS`: add sorted exact records for all four artifacts.
- `TRUST.md`: add the four GNU Netcat source records and the factual legacy
  DSA/SHA-1/key-expiry limitation; leave the artifacts absent from the
  independent-evidence exception table unless such evidence is actually
  produced.

## Implementation Sequence

1. Download the archive, signature, and official public key into temporary
   storage; verify the accepted checksum, exact fingerprint, signature, file
   size, licenses, and release provenance before copying identical mode-100644
   inputs into the four recipe directories.
2. Create the x86-64 recipe first, including the minimal address-copy patch,
   deterministic configure flags, link inventory, complete ELF checks, and
   loopback smoke test; run its syntax checks and real build to prove the
   recipe shape.
3. Copy the proven tool-owned recipe shape to AArch64, ARMv7, and x86, changing
   only platform, architecture/ABI checks, target triplet, and required x86 CPU
   flags. Keep source, feature, patch, and test behavior identical.
4. Before the remaining builds, warn that three emulated compilations and
   target tests may exceed ten minutes and provide an estimate. Build all
   remaining architectures through their locked builders and retain only fully
   validated outputs.
5. Add the four catalog rows together, update the complete checksum manifest
   and trust/source records, inspect binary sizes against repository hosting
   limits, and audit the diff for complete ready-architecture coverage.
6. Run focused checks and full repository validation, then commit and push the
   nc rollout and completed-plan record without staging unrelated work.

## Validation

- Run `bash -n` on host scripts, `sh -n` on guest and smoke scripts,
  `git diff --check`, and any recipe-validator unit tests affected by the new
  catalog rows.
- For every source copy, verify the exact SHA-256 and use `gpgv` with only the
  tracked keyring; require the full expected fingerprint and fail closed on any
  signature error. Independently verify the patch checksum and exact apply.
- For each candidate and installed artifact, use `file` and `readelf` to require
  the promised machine, class, endianness, ABI, stripped state, `ET_EXEC`, no
  `PT_INTERP`, and no `DT_NEEDED`. ARMv7 must be ELF32 little-endian hard-float;
  x86 must be ELF32 little-endian `Intel 80386` built with the i686/CMOV/SSE2
  baseline.
- Require the linker-map inventory to cover every linked archive and all rows
  to contain package/source, version, license, license text, and source
  evidence.
- On every target architecture, require GNU Netcat 0.7.1 version output and
  byte-exact TCP and UDP numeric-loopback transfers with bounded timeouts and
  no external network access.
- Require each installed artifact's SHA-256 to equal its validated candidate,
  then run `sha256sum -c artifacts/SHA256SUMS` and `./validate.sh`.
- Confirm exactly four enabled nc rows exist, no ready architecture is missing,
  and no BusyBox, socat, builder, generic dispatcher, root README, or
  architecture-policy file changed.

## Success Criteria

- A fresh checkout can run `./build.sh nc <architecture>` for every ready
  architecture using only the tracked inputs and locked builder.
- All four committed `nc` files are stripped, static, correctly labeled
  `ET_EXEC` executables that run and transfer TCP and UDP data on their promised
  architectures.
- Users can see that the artifact is GNU Netcat 0.7.1, uses GNU syntax, is
  IPv4-only, and comes from an old beta upstream release with legacy signature
  strength.
- Source, local patch, linked inputs, licenses, catalog state, checksums, and
  trust claims are complete and fail closed under repository validation.
- No BusyBox coupling, builder revision, generic framework, or unsupported
  feature claim is introduced.
