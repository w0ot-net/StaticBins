# Plan: Add rsync Across Ready Architectures

## Summary

Add rsync 3.4.4 for `aarch64`, `armv7`, `x86`, and `x86_64` with a deliberately
bounded static feature profile. Authenticate the current release with its
upstream signature, use bundled popt and zlib to avoid new builder
dependencies, and test both local incremental copies and the real rsync daemon
protocol on every target architecture.

## Problem

The repository lacks an efficient incremental file-transfer utility. A static
rsync is useful for rescue, deployment, and remote diagnostics, but its
configure result varies with whatever optional libraries happen to be visible.
That would make checksum, compression, ACL, xattr, crypto, and charset behavior
architecture- or builder-dependent unless the recipe fixes the feature set.

Version output alone is also weak coverage for rsync: it would not exercise the
client/server protocol, delta transfer, compression, archive metadata, or
daemon networking. The recipe needs controlled capability assertions and a
functional loopback daemon transfer.

## Scope

In scope:

- Add signed rsync 3.4.4 as `artifacts/<architecture>/rsync` on all four ready
  architectures.
- Enable IPv6, xattrs, standard archive behavior, daemon mode, and bundled zlib
  compression/popt option parsing.
- Disable ACLs, iconv, OpenSSL acceleration, xxHash, zstd, lz4, and manpage
  regeneration so the feature and link surface fits the current locked
  builders exactly.
- Validate local recursive/incremental metadata behavior and a compressed
  client-to-loopback-daemon transfer on each target architecture.
- Document optional-feature omissions and that remote-shell transfers require
  a separately supplied command such as `ssh`.

Out of scope:

- Bundling ssh, rsync-ssl, certificates, a daemon service definition, default
  `rsyncd.conf`, passwords, manpages, or runtime wrappers.
- ACL, charset conversion, xxHash, zstd, lz4, or OpenSSL support and the builder
  packages those features would require.
- Cross-version interoperability testing against external rsync servers,
  performance benchmarking, or byte-for-byte reproducibility claims.
- Builder publication, generic recipe refactoring, root README changes, or
  architecture-policy changes.

## Design

Use the official HTTPS `rsync-3.4.4.tar.gz` release archive with accepted
SHA-256
`bd88cf82fa653da32314fb229136407c5c90f80d1758d8f4b091767877d8fa96`.
Track its detached signature and an export-minimal keyring for Andrew Tridgell,
whose exact fingerprint is
`9FEF112DCE19A0DC7E882CB81BB24997A8535F6F`. The official rsync download page
identifies him as signer for 3.4.0 and later and directs users to fetch the key
for `andrew@tridgell.net`. Declare `pgp` and require the signature's RSA/SHA-512
fingerprint using only the tracked keyring.

Configure the release tarball, which already contains generated files, with
`--disable-md2man`, `--enable-ipv6`, `--enable-xattr-support`,
`--disable-acl-support`, `--disable-iconv`, `--disable-openssl`,
`--disable-xxhash`, `--disable-zstd`, `--disable-lz4`,
`--with-included-popt`, and `--with-included-zlib`. Do not run autotools,
Python, or network fetch helpers. Require configure's summary and target
`rsync --version` to report the intended invariant capability set; allow only
documented word-size/architecture optimization differences between 32- and
64-bit targets.

Compile with `-O2 -pipe`, add `-march=i686 -msse2 -mfpmath=sse` on x86, and
link with `-static` and a final map, without `-no-pie`. Select classic static
`ET_EXEC` and fail if a builder drifts to another type. If the existing builder
cannot satisfy the stated source-only dependencies, stop and handle that as a
separate builder revision rather than resolving packages inside the recipe.

The final link is expected to contain source-built popt and zlib archives plus
builder-owned runtime archives. Give the tool-owned archive inventory an
explicit origin kind: source-built rows resolve to the verified rsync archive
and its popt/zlib license files, while builder rows resolve through exact APK
ownership, version, Alpine license metadata, reviewed license text, and an
immutable aports URL. Require an exact one-to-one match with all archives seen
in the linker map.

Rsync is GPL-3.0-or-later and its included popt and zlib code has separate
permissive terms. Retain the main `COPYING`, `popt/COPYING`, zlib notice, musl,
and GCC runtime notices selected by the final link. OpenSSL and xxHash license
exceptions do not justify linking those disabled libraries and should not be
listed as active link inputs.

The target smoke test has two stages. First, create a source tree with regular
files, a nested directory, a symbolic link, and hard-linked files; run
`rsync -aH`, change one source file, rerun with deletion enabled, and compare
content and metadata relationships. Second, start the candidate itself as a
foreground daemon on a fixed high loopback port using a temporary explicit
config, transfer a second tree with `-az` to a writable module, stop the daemon,
and compare results. Use no external network, no ssh, bounded readiness loops,
timeouts, and reliable process cleanup. This exercises both ends of protocol
32 and the bundled compression code.

Host entry points use only Docker Buildx and the exact builder digest, export a
temporary candidate, run host ELF checks and target smoke tests, install after
success, repeat validation, and require candidate/installed hash equality.

## Affected Components

- `recipes/rsync/{aarch64,armv7,x86,x86_64}/`: add Dockerfiles, host/guest
  build scripts, smoke tests, READMEs, PGP source locks and tracked inputs, and
  source/builder license and archive inventories.
- `recipes/catalog.tsv`: add four enabled `rsync` rows.
- `artifacts/{aarch64,armv7,x86,x86_64}/rsync`: add four validated stripped
  executables.
- `artifacts/SHA256SUMS`: add sorted exact checksum records for all four files.
- `TRUST.md`: add four upstream-PGP rsync source records with the exact Andrew
  Tridgell fingerprint; add no independent artifact evidence unless it is
  actually obtained.

## Implementation Sequence

1. Fetch the release archive, detached signature, and officially directed key
   into temporary storage; verify the accepted SHA-256, exact fingerprint and
   signature, release/version status, file size, and all selected license texts
   before copying identical mode-100644 inputs into each recipe.
2. Implement and really build the x86-64 recipe first. Lock the configure
   summary, source/builder archive inventory, static ELF profile, and both
   stages of the smoke test before copying the recipe shape.
3. Add AArch64, ARMv7, and x86 recipes with identical source and feature flags,
   changing only platform, target/ABI checks, triplets, and x86 baseline flags.
   Define architecture-specific allowed version-output differences explicitly.
4. Warn that the remaining emulated builds and daemon smoke tests may exceed
   ten minutes and provide an estimate. Build all three through their locked
   builders and keep only candidates passing local and protocol tests.
5. Add all four catalog rows together, update manifest and trust records,
   review artifact sizes and GPL source availability, and confirm omitted
   optional libraries did not enter any link map.
6. Run focused and full repository validation, then commit and push only the
   complete rsync rollout and completed-plan record.

## Validation

- Run `bash -n` on host scripts, `sh -n` on guest/smoke scripts,
  `git diff --check`, and checks for the exact configure option set.
- For every architecture, verify the archive SHA-256 and detached signature
  with only the tracked minimal keyring; require the full signer fingerprint
  and fail closed on any PGP error.
- Require configure and target version output to show rsync 3.4.4, protocol 32,
  IPv6, xattrs, symlink/hardlink support, zlib compression, and no ACLs, iconv,
  OpenSSL crypto, xxHash, zstd, or lz4. Do not require architecture-specific
  SIMD or C word-size lines to match across targets.
- Parse the final linker map and require exact coverage of source-built popt/
  zlib and every builder archive with correct versions, licenses, texts, and
  source evidence.
- Require correct machine, class, endianness, ABI, stripping, classic
  `ET_EXEC`, no `PT_INTERP`, and no `DT_NEEDED` for candidates and installed
  outputs; include ARMv7 hard-float and x86 i686/CMOV/SSE2 checks.
- On each target, require successful two-pass local `-aH` synchronization with
  deletion and link checks, then a compressed loopback daemon transfer using
  the candidate on both client and server sides.
- Require installed/candidate hash equality, run
  `sha256sum -c artifacts/SHA256SUMS`, and run `./validate.sh`.
- Confirm four ready-architecture rows/artifacts exist and no ssh wrapper,
  daemon service, builder, generic framework, root README, or architecture
  policy changed.

## Success Criteria

- A fresh checkout can run `./build.sh rsync <architecture>` for every ready
  architecture from only tracked signed source and the committed builder
  digest.
- All four files are stripped static `ET_EXEC` rsync 3.4.4 binaries that pass
  local incremental/archive tests and a real compressed daemon-protocol
  transfer on their promised host architectures.
- Capabilities are consistent and explicit: IPv6, xattrs, daemon mode, bundled
  zlib and popt are present; ACL, iconv, OpenSSL, xxHash, zstd, and lz4 are
  absent and documented.
- Main, popt, zlib, runtime, source-authentication, checksum, catalog, and trust
  records are complete and fail closed.
- The rollout introduces no hidden package resolution, ssh/runtime bundle,
  service configuration, generic abstraction, or unsupported assurance claim.
