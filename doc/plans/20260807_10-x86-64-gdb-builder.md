# Plan: Expand the x86-64 Builder for GDB

## Summary

Publish one new immutable x86-64 builder revision containing the exact static
dependencies needed by the existing GDB feature profile. Adopt its digest as a
separate maintainer operation, then qualify every current x86-64 recipe against
the new locked environment before the GDB recipe is added.

Execute this plan after the AArch64 tcpdump plan and before the x86-64 GDB plan.

## Problem

The current x86-64 builder supports GDBserver, lsof, socat, strace, and tcpdump
but lacks GDB's GMP, MPFR, ncurses, compression, and related static development
inputs. Recipes may not resolve packages themselves, and the single
architecture lock means changing the builder also changes the environment used
by every existing x86-64 recipe.

## Scope

In scope:

- Add only the direct packages and candidate probes required by the current
  reduced GDB 17.2 profile to `builders/x86_64/`.
- Publish the next non-replaceable `x64-alpine-3.24.1-r3` builder, verify it
  anonymously, and commit its immutable digest.
- Rebuild each existing x86-64 recipe once with the committed r3 digest and
  require its installed artifact to reproduce the pre-change bytes.
- Update the nearest builder documentation for the new version.

Out of scope:

- Adding the GDB recipe or artifact; that is the following plan.
- Updating Alpine, changing existing package versions or utility feature
  profiles, or adding packages for unknown future tools.
- Replacing existing artifacts when qualification differs; a mismatch must
  stop execution and trigger plan review instead of silently widening scope.

## Design

Derive the additions from `recipes/gdb/aarch64/build-in-container.sh` and the
AArch64 builder lock: the exact command set and static archives for Expat, GMP,
MPFR, ncurses, xz, zlib, and zstd, plus any directly consumed build utilities.
Resolve exact x86-64 package versions against the already pinned Alpine 3.24.1
base and retain the current packages unchanged. Extend the candidate validation
to compile and execute a static C++ probe linked against the GDB archive set and
to verify package ownership, license metadata, ELF64 x86-64 identity, and lack
of dynamic dependencies.

Builder publication remains separate from artifact work. Validate the local
candidate, publish r3 once through the generic publisher, inspect both tags and
the reported digest anonymously, then make a local builder-adoption commit.
Only after that commit may the five existing recipes consume r3. Preserve the
current artifact bytes outside the worktree, rebuild through each public
command one time with native BuildKit cache, and compare the results with the
pre-change snapshot. Restore the preserved bytes and stop without pushing if
any qualification differs; do not add a retry. Push the builder-adoption commit
only after all five artifacts reproduce exactly.

## Affected Components

- `builders/x86_64/packages.lock`: add the exact GDB dependency package set.
- `builders/x86_64/build.sh`: validate the new archives and static C++ link
  without weakening existing builder probes.
- `builders/x86_64/environment.lock`: advance to the r3 tag and verified digest.
- `README.md`: update the published x86-64 builder identifier.
- `doc/architecture/build/BUILD_ENVIRONMENTS.md`: record the expanded current
  consumer set and immutable revision.

## Implementation Sequence

1. Snapshot the r2 builder state and every x86-64 artifact hash. Resolve the
   minimal GDB package additions against the pinned Alpine child manifest.
2. Advance the candidate to r3, extend its all-at-once package/archive/static
   probes, and run it once with retained BuildKit cache.
3. Publish r3 exactly once, anonymously verify platform, labels, packages,
   SBOM, provenance, and probe execution, then create the separate local
   `BUILDER_IMAGE` adoption commit without pushing it yet.
4. Preserve the five artifact files, rebuild GDBserver, lsof, socat, strace,
   and tcpdump once each through the committed lock, and require every hash to
   match its snapshot. Restore the preserved files and stop on any mismatch.
5. Run repository validation and push the adoption commit only after proving
   that no artifact or recipe changed.

## Validation

- Run `bash -n builders/x86_64/build.sh builders/publish.sh`, focused builder
  catalog tests, `git diff --check`, and `./validate.sh`.
- Run `./builders/x86_64/build.sh`; require exact package inventory, every GDB
  archive, a successful static C++ link and execution, ELF64 x86-64 identity,
  no interpreter, no `DT_NEEDED`, and the existing probes.
- Run `./builders/publish.sh x86_64` once for r3 and anonymously inspect the
  immutable digest, versioned/floating tags, OCI platform, labels, SBOM, and
  provenance.
- After the local digest-adoption commit, run the five existing
  `./build.sh <tool> x86_64` commands once, compare all artifact hashes with the
  pre-change snapshot, and verify the preserved copies permit exact restoration
  on failure.
- Confirm `recipes/catalog.tsv`, recipe files, `artifacts/SHA256SUMS`, TRUST
  records, and artifact bytes remain unchanged.

## Success Criteria

- The committed x86-64 environment lock names a verified immutable r3 builder
  that contains every dependency required by the planned GDB recipe.
- Every existing x86-64 artifact reproduces exactly under r3 without feature or
  recipe changes.
- Builder publication remains separate from the following GDB artifact change.
