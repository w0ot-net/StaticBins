# Plan: Add the x86 strace Recipe and Binary

## Summary

Add strace 6.16 as a reproducible static 32-bit x86 executable with its native
personality only. Validate it in a checksum-pinned full-system x86 guest so
known syscalls are decoded through a real 32-bit kernel ptrace path.

## Problem

strace is available for the other architectures but not x86. Its useful
functional boundary is ptrace plus syscall decoding, which cannot be proven by
`--version` or assumed to work through QEMU user-mode emulation on every host.

## Scope

In scope:

- Add `recipes/strace/x86/` using the tracked strace 6.16 source,
  checksum-only assurance, bundled UAPI profile, licenses, link inventory, and
  static smoke helpers.
- Pin an official versioned Alpine x86 kernel in a tool-owned `vm.lock` and boot
  a generated diskless `qemu-system-i386` guest for the ptrace test.
- Add `artifacts/x86/strace` plus catalog, checksum, README, and TRUST records.

Out of scope:

- Enabling compatibility personalities, stack unwinding, libiberty, SELinux
  contexts, or updating strace.
- Sharing VM files with GDBserver, committing kernel/VM images, or changing
  existing strace recipes.
- Adding independent exact-rebuild or attestation claims.

## Design

Port the AArch64/ARMv7 full-system design and preserve `--enable-mpers=no`,
bundled Linux UAPI headers, no external unwind/libiberty/SELinux dependencies,
link-map reconciliation, and the known `openat`, marker `write`, and
`exit_group(0)` assertions. Determine and lock the exact native x86 feature
line produced by the builder; do not guess or describe native x86 as a
compatibility personality.

Compile strace and helpers with `-march=i686 -msse2 -mfpmath=sse`. Require
static ELF32 little-endian x86 `ET_EXEC`, no interpreter, and no `DT_NEEDED`,
with the distributed candidate stripped. Evidence-select and pin an official
Alpine x86 kernel/PC-machine/CPU combination with the required serial,
initramfs, ptrace, and syscall support. The PID 1 harness must trace a direct
child and emit a bounded success marker only after every syscall assertion.
Preserve compiled output for late VM-validation corrections.

## Affected Components

- `recipes/strace/x86/`: add source, build scripts, VM lock/harness, helpers,
  licenses, inventory, and documentation.
- `artifacts/x86/strace`: add the validated executable.
- `recipes/catalog.tsv`: enable `(strace, x86)`.
- `artifacts/SHA256SUMS`: add the sorted exact digest.
- `README.md`: add x86 strace availability and rebuild support.
- `TRUST.md`: record source limitation, kernel input, recipe validation, and
  no independent evidence.

## Implementation Sequence

1. Require the committed x86 builder and evidence-select/pin the official x86
   kernel plus QEMU machine/CPU invocation.
2. Port recipe and helpers, establish the exact native feature line and archive
   inventory, and run syntax/warning checks.
3. Announce the expected emulated duration, build once, retain its output, and
   run version, ELF, link, and full-system syscall validation.
4. Add the artifact and shared records after the VM marker, then validate,
   commit, and push explicit paths.

## Validation

- Run source checksum validation, shell syntax and C warning checks,
  `git diff --check`, and `./validate.sh`.
- Run `./build.sh strace x86` once; require the exact native feature line,
  complete link inventory, verified kernel, and direct-child syscall assertions.
- Inspect strace and helpers with `file`/`readelf`; require the CPU baseline,
  ELF32 little-endian x86 `ET_EXEC`, no interpreter, no `DT_NEEDED`, and the
  intended stripping state.
- Verify and rerun the installed artifact through the VM harness without
  recompilation.

## Success Criteria

- A fresh checkout builds the committed static x86 strace from tracked source
  and the immutable builder.
- A pinned full-system guest proves real ptrace and exact syscall decoding.
- Existing strace profiles, artifacts, and assurance records remain unchanged.
