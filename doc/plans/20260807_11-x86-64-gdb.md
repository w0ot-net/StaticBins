# Plan: Add the x86-64 GDB Recipe and Binary

*Distilled: 2026-08-07*

## Summary

Add GNU GDB 17.2 as a reproducible static x86-64 executable using the expanded
immutable builder. Preserve the existing reduced GDB feature profile and GNU
source authentication, and prove BFD and symbol handling with a deterministic
batch-mode target inspection test.

Execute this plan only after the x86-64 r3 builder plan is committed and pushed.

## Problem

GDB is the only current utility missing from x86-64. The AArch64 recipe owns a
reviewed source, static-link inventory, and feature profile, while the planned
builder expansion supplies the same dependencies on x86-64; no x86-64 recipe,
artifact, or assurance record connects those pieces.

## Scope

In scope:

- Add `recipes/gdb/x86_64/` with exact copies of the GNU-signed GDB 17.2
  inputs, reviewed licenses, current configure profile, and architecture-owned
  final-link inventory.
- Add a small symbol-bearing x86-64 smoke target and deterministic batch-mode
  assertions for target loading, architecture reporting, symbol lookup, and
  data evaluation.
- Build and commit `artifacts/x86_64/gdb` plus catalog, checksum, README, and
  TRUST records.
- Make every existing GDB recipe README use an architecture-qualified root
  command after GDB becomes multi-architecture.

Out of scope:

- Enabling Python, Guile, debuginfod, Babeltrace, Intel PT, simulators, or
  bundled binutils tools, or updating GDB.
- Changing the AArch64 or ARMv7 GDB recipes or the newly adopted builder.
- Requiring ptrace or a full VM when deterministic file inspection proves the
  selected static runtime and BFD path.

## Design

Port the AArch64 recipe and incorporate the focused batch target design from
the ARMv7 GDB plan. Preserve the authenticated source bytes, signature,
keyring, exact GNU fingerprint, configure switches, libtool `-all-static`
link, link map, and complete archive reconciliation. Adapt the compiler triplet
and every external archive path to the locked x86-64 builder rather than
copying AArch64 paths.

Use a supported non-PIE static link and require a stripped ELF64 little-endian
x86-64 `ET_EXEC`, no interpreter, and no `DT_NEEDED`; if the locked toolchain
cannot produce that profile without build-system rewriting, stop and revise
the plan. Keep the test-only target unstripped with a known data symbol, and run
GDB with `--batch --nx` under `linux/amd64` to assert the expected architecture,
symbol address, and value before installing the candidate.

## Affected Components

- `recipes/gdb/x86_64/`: add authenticated inputs, build scripts, licenses,
  link inventory, smoke target, and recipe documentation.
- `recipes/gdb/{aarch64,armv7}/README.md`: remove any abbreviated root command
  that the final multi-architecture GDB catalog would reject.
- `artifacts/x86_64/gdb`: add the validated executable.
- `recipes/catalog.tsv`: enable `(gdb, x86_64)`.
- `artifacts/SHA256SUMS`: add the sorted exact digest.
- `README.md`: list x86-64 GDB and its rebuild path.
- `TRUST.md`: record GNU source authentication, committed recipe validation,
  and `None` for independent evidence.

## Implementation Sequence

1. Require the committed r3 x86-64 builder and snapshot existing GDB artifacts
   and recipe source/evidence bytes.
2. Port the AArch64 owner, adapt only target values and archive inventory, add
   the warning-clean smoke target and batch assertions, and qualify every GDB
   recipe README command with its architecture.
3. Announce the expected duration if needed, build once with retained cache,
   and require source, link, ELF, version, and focused target checks.
4. Add the artifact and shared records, run repository validation, then commit
   and push explicit paths.

## Validation

- Run offline PGP validation, shell syntax and C warning checks,
  `git diff --check`, and `./validate.sh`.
- Byte-compare the GDB archive, signature, keyring, and upstream license texts
  with the validated AArch64 owner.
- Compare every `./build.sh gdb` command in the root and GDB recipe READMEs with
  `./build.sh list`; require an explicit architecture wherever more than one
  GDB catalog row exists.
- Run `./build.sh gdb x86_64` once; require exact version, complete link
  inventory, and deterministic batch architecture/symbol/data assertions.
- Inspect candidate, smoke target, and installed artifact with `file`,
  `readelf`, and `sha256sum`; require the candidate/artifact to be stripped
  static ELF64 x86-64 `ET_EXEC` files while the target retains its test symbol.

## Success Criteria

- A fresh checkout builds the committed x86-64 GDB from authenticated tracked
  source and the immutable r3 builder.
- The artifact passes exact static ELF and focused BFD/symbol inspection tests.
- Existing GDB artifacts, feature policy, and assurance claims remain unchanged.
