# Plan: Add the x86 socat Recipe and Binary

*Distilled: 2026-08-07*

## Summary

Add socat 1.8.1.3 as a reproducible static 32-bit x86 executable. Port the
existing LibreSSL/SCTP feature profile and focused TCP, Unix-socket, and TLS
data-path smoke suite to the documented i686/CMOV/SSE2 baseline.

Execute this plan after `20260807_14-x86-tcpdump.md` establishes the x86
artifact and contributor contracts.

## Problem

socat is available for AArch64, ARMv7, and x86-64 but not x86. The full-suite
x86 builder has the established static dependencies, while no x86 recipe or
artifact exposes them through the repository contract.

## Scope

In scope:

- Add `recipes/socat/x86/` using the exact tracked socat source, explicit
  checksum-only assurance, licenses, link inventory, and current feature policy.
- Retain the focused TCP, Unix-socket, and ephemeral LibreSSL TLS relay tests
  and enforce static x86 ELF and CPU-baseline checks.
- Add `artifacts/x86/socat` and the required catalog, checksum, README, and
  TRUST records.

Out of scope:

- Updating socat; replacing the locked LibreSSL TLS implementation with
  OpenSSL; disabling the currently enabled SCTP or TLS support; or enabling
  the currently omitted readline, libwrap, or FIPS integrations.
- Refactoring the other socat recipes or changing the x86 builder.
- Adding independent rebuild or attestation claims without evidence.

## Design

Port `recipes/socat/x86_64/` and preserve the exact source lock, tracked
archive, licenses, configure switches, static link inventory, version/feature
checks, and deterministic TCP, Unix-socket, and TLS relay smoke suite. Preserve
SCTP and the `WITH_OPENSSL`-compatible TLS interface backed by the builder's
locked LibreSSL 4.3.1 static archives; continue to reject readline, libwrap,
and FIPS. Adapt only the target triplet, platform/binfmt spelling, explicit x86
baseline flags, archive paths, and ELF validation. Keep tool-specific logic in
the recipe rather than adding an x86 branch to generic orchestration.

The candidate and installed artifact must be stripped ELF32 little-endian
`Intel 80386` `ET_EXEC` files compiled with
`-march=i686 -msse2 -mfpmath=sse`, with no interpreter or `DT_NEEDED`. Execute
the smoke test under `linux/386` with public networking disabled. Require exact
payload transfer over loopback TCP, a Unix socket, and an ephemeral
certificate-backed LibreSSL TLS relay before replacement.

## Affected Components

- `recipes/socat/x86/`: add the x86 recipe, source, notices, link inventory,
  and smoke test.
- `artifacts/x86/socat`: add the validated executable.
- `recipes/catalog.tsv`: enable `(socat, x86)`.
- `artifacts/SHA256SUMS`: add the sorted exact digest.
- `README.md`: add x86 socat availability and rebuild support.
- `TRUST.md`: add factual source and passed recipe-validation records with
  `None` for independent evidence.

## Implementation Sequence

1. Snapshot existing socat sources and artifact hashes and require the committed
   full-suite x86 builder.
2. Copy the nearest recipe, adapt only architecture-owned values, and run fast
   syntax/source checks.
3. Run `./build.sh socat x86` once with reusable BuildKit cache and require all
   link, version, feature, TCP, Unix-socket, and TLS assertions.
4. Add the artifact and live records, run repository validation, then commit
   and push explicit paths.

## Validation

- Byte-compare source and reviewed license inputs with an existing socat owner;
  run shell syntax, `git diff --check`, and `./validate.sh`.
- Run `./build.sh socat x86` once and require exact source checksum, complete
  archive inventory, the exact enabled/disabled feature macros, and successful
  TCP, Unix-socket, and ephemeral LibreSSL TLS payload transfers with public
  networking disabled.
- Use `file`, `readelf`, and `sha256sum` to prove the explicit CPU baseline,
  ELF32 little-endian x86 `ET_EXEC`, stripping, no interpreter, no
  `DT_NEEDED`, and candidate/install byte equality.

## Success Criteria

- A fresh checkout recreates `artifacts/x86/socat` with one public build command.
- The binary satisfies the same LibreSSL/SCTP feature, linked-input, and
  three-relay functional contract as the existing socat artifacts.
- Existing socat artifacts and records remain unchanged.
