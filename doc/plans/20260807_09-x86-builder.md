# Plan: Add the 32-bit x86 Builder Foundation

## Summary

Add `builders/x86/` and publish one immutable Alpine 3.24.1 builder for OCI
platform `linux/386`. Define the target as Alpine's 32-bit x86 ABI: ELF32,
little-endian, i686-compatible, with CMOV and SSE2. Keep recipe allowlists and
artifact claims unchanged until the ordered tcpdump plan consumes the locked
builder and proves a real `x86` artifact.

Execute this plan after the open ARMv7 plans have stopped changing
`builders/publish.sh`, `README.md`, or the build-environment documentation, and
before `20260807_10-x86-tcpdump.md`.

## Problem

The repository has no 32-bit x86 build environment. The local publisher accepts
only `aarch64`, `armv7`, and `x86_64`, and ordinary recipes may consume only an
already-published builder digest. Adding `x86` directly to the recipe allowlists
would therefore advertise an architecture whose required immutable environment
does not exist.

Alpine names this port `x86` and defines it as 32-bit i686-compatible with CMOV
and SSE2. Docker and OCI expose the same image as `linux/386`; the pinned Alpine
3.24.1 index currently identifies its `linux/386` child as
`sha256:6f5908cdf811d574b30ec394e405ef74ee293bed5af1620a5187d604604a90a8`.
These different spellings must remain boundary translations rather than leak
into repository paths.

Relevant platform authorities:

- [Alpine's architecture matrix](https://wiki.alpinelinux.org/wiki/Include%3AArchitecture_support_matrix)
  defines the `x86` CPU baseline.
- [Docker's builder documentation](https://docs.docker.com/build/builders/)
  uses `linux/386` as the container platform.
- [The OCI image configuration specification](https://github.com/opencontainers/image-spec/blob/main/config.md)
  derives architecture values from GOARCH, where 32-bit x86 is `386`.
- [The pinned binfmt helper](https://github.com/tonistiigi/binfmt) exposes
  `linux/386` through `qemu-i386` when native execution is unavailable.

## Scope

In scope:

- Create a digest-pinned Alpine 3.24.1 `linux/386` builder under
  `builders/x86/` with the smallest direct package set needed by the ordered
  tcpdump recipe.
- Validate exact packages, required build commands and archives, the Alpine
  package architecture, OCI architecture, and executable static x86 probes.
- Extend the existing local publisher with a literal `x86` case using
  `linux/386`, `x86-*` versioned tags, and `x86-latest`.
- Publish a non-replaceable `x86-alpine-3.24.1-r1` builder with SBOM and
  provenance, verify it anonymously, and adopt its immutable digest.
- Document the available builder and its platform translation without yet
  claiming a distributed `x86` utility.

Out of scope:

- Adding `x86` to `build.sh`, `scripts/recipes.py`, `AGENTS.md`, or the
  contributor-facing recipe architecture list before an artifact exists.
- Adding a catalog row, recipe, artifact directory, checksum, or trust record;
  those belong to the ordered tcpdump plan.
- Preinstalling dependencies for GDB, GDBserver, lsof, socat, strace, or other
  future consumers.
- Supporting i386, i486, i586, x32, DOS/Windows executables, or a CPU without
  CMOV and SSE2.
- Refactoring the four architecture-owned builders or introducing a generated
  platform registry for one additional concrete case.

## Design

Use these exact translations:

| Concern | Value |
| --- | --- |
| Repository and Alpine identifier | `x86` |
| CPU baseline | i686-compatible with CMOV and SSE2 |
| Docker/Buildx platform | `linux/386` |
| OCI architecture | `386` |
| ELF contract | ELF32, little-endian, machine `Intel 80386`, `ET_EXEC` |
| binfmt installation target | `386` (`qemu-i386`) |
| Builder tags | `x86-alpine-3.24.1-r1`, `x86-latest` |

Reuse the architecture-owned builder layout. `environment.lock` pins the
Alpine `linux/386` child manifest, the existing binfmt helper digest, the
non-replaceable tag, and finally the published builder digest. Reconfirm the
Alpine child descriptor during execution rather than trusting the value copied
into this plan. `packages.lock` records exact direct packages resolved from
that base. Start from the observed tcpdump requirements--the static C
toolchain, Linux headers, Flex, Bison, file and tar support--and retain a direct
package only when the candidate or tcpdump probe consumes it. Ordinary recipes
must not run `apk add` or resolve a replacement package set.

Follow the existing Buildx-only candidate path. Check Docker and Buildx before
pulling images, registering emulation, creating output, or compiling. First try
the pinned `linux/386` Alpine image directly; an x86-64 Linux kernel may execute
it through native 32-bit compatibility. Only if that fails, install `386` from
the pinned binfmt image and prove the image executes before continuing.

Do not use `uname -m` as the x86 identity invariant: a 32-bit container shares
the host kernel and may report differently between native compatibility and
QEMU paths. Validate actual target state instead: require `apk --print-arch` to
report `x86`, inspect `/bin/sh` and compiled probes as ELF32 little-endian
`Intel 80386`, and inspect the loaded and published image as OCI `386`. Compile
with an explicit i686/CMOV/SSE2-compatible baseline, reject an interpreter and
all `DT_NEEDED` entries, and execute every probe through `linux/386`.

Add a bounded `x86` branch to `builders/publish.sh`; do not generalize its
architecture mapping. The publisher continues to refuse an existing versioned
tag, invoke the candidate validator, publish through Buildx with SBOM and
provenance, verify the one expected platform, and print the digest assignment.
Publish first, inspect the result, then commit `BUILDER_IMAGE`; never substitute
a mutable tag or another architecture's builder.

## Affected Components

- `builders/x86/{Dockerfile,packages.lock,environment.lock,build.sh}`: own and
  validate the pinned 32-bit x86 build environment.
- `builders/publish.sh`: accept the bounded `x86` publication mapping and tags.
- `doc/architecture/build/BUILD_ENVIRONMENTS.md`: record the builder identity,
  CPU baseline, and `linux/386` translation while distinguishing builder
  availability from recipe support.
- `README.md`: list the published x86 builder and maintainer publication
  command without adding a ready-to-run x86 row.

## Implementation Sequence

1. Start after shared ARMv7 builder/publication work is complete and the
   worktree is clean. Reconfirm the Alpine 3.24.1 `linux/386` child digest and
   resolve the minimal direct package versions against that exact base.
2. Add the four `builders/x86/` files under the `x86-alpine-3.24.1-r1` tag with
   `BUILDER_IMAGE` intentionally absent. Extend `builders/publish.sh` with only
   the fixed x86 mapping.
3. Run the local candidate once, retaining BuildKit cache and diagnostic output
   for late validation corrections. Require package, command, archive,
   baseline, static ELF, execution, OCI-platform, and source-label checks to
   pass together.
4. Run `./builders/publish.sh x86`. Require the versioned tag to be unused,
   inspect the reported digest and both tags anonymously, and verify the
   platform, package inventory, labels, SBOM, provenance, and probe execution.
5. Add only that verified digest as `BUILDER_IMAGE`, update the two owning
   documents, rerun focused and repository validation, then commit and push the
   complete locked builder foundation.

## Validation

- Run `bash -n builders/x86/build.sh builders/publish.sh` and
  `git diff --check`.
- Run `./builders/x86/build.sh`; require the exact package lock, promised
  commands and archives, Alpine `x86` identity, OCI `386` identity, and
  executable static probes to pass.
- For each probe, require ELF32, little-endian data, machine `Intel 80386`,
  `ET_EXEC`, no requested interpreter, no `DT_NEEDED`, and successful
  `linux/386` execution.
- Run `./builders/publish.sh x86` exactly once for the new r1 tag. Inspect the
  reported digest and versioned/floating tags anonymously and confirm one
  `linux/386` manifest plus the expected labels, SBOM, and provenance.
- Run `./validate.sh` and confirm `./build.sh list`, `recipes/catalog.tsv`,
  `artifacts/SHA256SUMS`, and every distributed artifact remain unchanged.

## Success Criteria

- `builders/x86/environment.lock` names one publicly pullable, immutable
  `linux/386` builder whose base and direct package inputs are exact.
- The candidate and published image prove the documented Alpine x86 baseline
  with executable static ELF32 probes and no mutable fallback.
- `./builders/publish.sh x86` is the single bounded maintainer publication
  command for the builder.
- The repository does not yet accept an `x86` catalog row or claim an x86
  utility; activation occurs only in the ordered tcpdump plan.
