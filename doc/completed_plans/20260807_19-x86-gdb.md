# Plan: Add the x86 GDB Recipe and Binary

*Distilled: 2026-08-07*

## Summary

Add GNU GDB 17.2 as a reproducible static 32-bit x86 executable with the
existing reduced feature profile. Use a deterministic batch-mode target
inspection test to prove the static runtime, BFD target loading, and symbol
handling without requiring ptrace.

Execute this plan after `20260807_14-x86-tcpdump.md` establishes the x86
artifact and contributor contracts.

## Problem

The full GDB client is absent from x86 even though the full-suite builder was
designed to provide its static dependency set. The repository needs a complete
x86 recipe owner, authenticated source, architecture-specific link evidence,
artifact, and functional validation.

## Scope

In scope:

- Add `recipes/gdb/x86/` with exact GNU-signed GDB 17.2 inputs, the current
  curses/Expat/compression profile, licenses, and x86 archive inventory.
- Add a symbol-bearing 32-bit x86 smoke target and deterministic batch
  assertions for architecture, symbol resolution, and data evaluation.
- Add `artifacts/x86/gdb` plus catalog, checksum, README, and TRUST records.

Out of scope:

- Enabling Python, Guile, debuginfod, source-highlight, Babeltrace, Intel PT,
  simulators, or bundled binutils tools, or updating GDB.
- Requiring local inferior execution/ptrace, changing the x86 builder, or
  refactoring existing GDB recipes.
- Adding independent rebuild or provenance claims without qualifying evidence.

## Design

Port the nearest GDB recipe while preserving the exact archive, detached
signature, minimal keyring, GNU fingerprint, configure profile, libtool
`-all-static` link, link map, and complete archive reconciliation. Adapt the
triplet and compiler-owned archive paths to the committed x86 builder, and add
`-march=i686 -msse2 -mfpmath=sse` consistently to GDB and the smoke target.

Use the toolchain's supported non-PIE static link and require a stripped ELF32
little-endian `Intel 80386` `ET_EXEC` with no interpreter or `DT_NEEDED`. If
that cannot be produced without Makefile rewriting, stop and revise the plan.
Keep the test target unstripped with a known non-optimized data symbol, then run
GDB with `--batch --nx` under `linux/386` to load it, report the expected x86
architecture, resolve the symbol, and evaluate its value before installation.

## Affected Components

- `recipes/gdb/x86/`: add authenticated inputs, build scripts, licenses, link
  inventory, smoke target, and documentation.
- `artifacts/x86/gdb`: add the validated executable.
- `recipes/catalog.tsv`: enable `(gdb, x86)`.
- `artifacts/SHA256SUMS`: add the sorted exact digest.
- `README.md`: add x86 GDB availability and rebuild support.
- `TRUST.md`: add GNU authentication, passed recipe validation, and `None` for
  independent evidence.

## Implementation Sequence

1. Require the committed full-suite x86 builder and snapshot existing GDB
   source/evidence and artifact hashes.
2. Port source, licenses, scripts, inventory, and smoke target; adapt only
   architecture-owned values and run fast offline checks.
3. Announce the expected emulated duration, build once with retained cache,
   and require the complete link, version, ELF, and batch target assertions.
4. Add artifact and live records, run repository validation, then commit and
   push explicit paths.

## Validation

- Run offline GNU PGP verification, shell syntax and C warning checks,
  `git diff --check`, and `./validate.sh`.
- Byte-compare source/evidence and shared license text with an existing GDB
  owner; run `./build.sh gdb x86` once.
- Require exact version, complete linked-archive inventory, explicit CPU flags,
  and deterministic architecture/symbol/data batch assertions.
- Inspect candidate, smoke target, and installed artifact with `file`,
  `readelf`, and `sha256sum`; require static ELF32 little-endian x86 `ET_EXEC`,
  no interpreter/`DT_NEEDED`, stripped release output, and the retained test
  symbol only in the helper.

## Success Criteria

- The committed GDB is a stripped static x86 executable built from
  authenticated source and the immutable full-suite builder.
- The focused target test proves BFD loading, architecture reporting, symbol
  lookup, and data evaluation on 32-bit x86.
- Existing GDB bytes, features, and assurance records remain unchanged.
