# Plan: Add the ARMv7 tcpdump Recipe and Binary

*Distilled: 2026-08-07*

## Summary

Add tcpdump 4.99.4 with libpcap 1.10.4 as a reproducible, stripped static
ARMv7 executable. Port the existing x86-64 feature profile and deterministic
packet-capture smoke test directly into one conventional ARMv7 recipe, using
the expanded immutable ARMv7 builder.

## Problem

tcpdump is distributed only for x86-64. The repository has an ARMv7 builder
and generic catalog support, but no `tcpdump/armv7` recipe, executable, source
record, or trust entry.

## Scope

In scope:

- Add one complete `recipes/tcpdump/armv7/` owner using the existing tracked
  tcpdump/libpcap bytes, PGP evidence, feature policy, licenses, link inventory,
  and offline smoke test.
- Build and commit `artifacts/armv7/tcpdump`, its catalog and checksum records,
  and live README/TRUST entries.
- Require ARMv7-specific ELF32, little-endian, ARM hard-float, static-link,
  stripping, version, BPF compilation, and deterministic pcap decoding checks.

Out of scope:

- Updating tcpdump or libpcap versions or enabling crypto, remote capture, USB,
  netmap, Bluetooth, D-Bus, RDMA, libnl, or hardware-vendor backends.
- Refactoring the x86-64 recipe into shared scripts, changing its bytes, or
  changing its historical independent attestation evidence.
- Adding an independent rebuild service or new attestation for the ARMv7
  artifact.

## Design

Create the ARMv7 recipe beside `recipes/tcpdump/x86_64/` and preserve its two
source records in one `source.lock`, GNU Privacy Guard evidence, configure
switches, link-map reconciliation, license inventory, and `smoke-test.sh`.
Copy the already reviewed regular source/evidence files into the new recipe and
verify their checksums and signatures; do not download replacement bytes.

Translate only the recipe boundary: use `builders/armv7/environment.lock`, OCI
platform `linux/arm/v7`, binfmt target `arm`, output
`artifacts/armv7/tcpdump`, and the locked ARMv7 compiler triplet/archive paths.
Both guest and host validation must use `file` and `readelf` to require ELF32,
little-endian data, machine `ARM`, hard-float EABI flags, `ET_EXEC`, no program
interpreter, no `DT_NEEDED`, and no debug or full symbol table. Run the existing
offline version/filter/pcap smoke test inside the target container before
installing the candidate.

Add the catalog row only with the validated artifact present. Record the
source authentication separately for tcpdump and libpcap in `TRUST.md`, state
that the artifact was maintainer-built through the committed recipe, and
record that no independent rebuild evidence is available.

## Affected Components

- `recipes/tcpdump/armv7/*`: own the ARMv7 build, tracked sources and PGP
  evidence, configuration, smoke test, licenses, and final-link inventory.
- `artifacts/armv7/tcpdump`: add the validated executable.
- `recipes/catalog.tsv`: enable the `tcpdump, armv7` identity.
- `artifacts/SHA256SUMS`: add the sorted exact artifact digest.
- `README.md`: add ARMv7 availability and rebuild links.
- `TRUST.md`: add both source-authentication records, the local recipe build
  record, and the absence of independent rebuild evidence.

## Implementation Sequence

1. Require the ARMv7 r2 builder plan to be complete and anonymously usable by
   digest.
2. Copy the reviewed source/evidence and license inputs, port the scripts and
   inventory, and verify the locked compiler triplet and compiler-owned archive
   paths inside the builder.
3. Run the direct recipe build once under ARMv7 execution. Validate the
   candidate and smoke test before allowing it to replace the artifact path.
4. Add the catalog, manifest, README, and TRUST records; stage only the explicit
   recipe/artifact/live-record paths and run repository validation.
5. Run the root local validation command, commit the port, and push it.

## Validation

- Run PGP verification through `python3 scripts/recipes.py validate` after the
  new regular source/evidence files are staged with mode `100644`.
- Run `./validate.sh` and `git diff --check`; dispatcher listing must show both
  tcpdump architectures and tcpdump must now require an explicit architecture.
- Run `./build.sh tcpdump armv7` and the focused offline tcpdump smoke test.
- Recheck the installed artifact with `file`, `readelf`, `sha256sum`, and
  `artifacts/SHA256SUMS`.
- Confirm the existing x86-64 tcpdump artifact and its historical independent
  attestation evidence remain unchanged.

## Success Criteria

- A fresh checkout can build `artifacts/armv7/tcpdump` from only the committed
  recipe inputs and immutable ARMv7 builder.
- The committed binary is a stripped static ARMv7 hard-float executable and
  passes the exact version, BPF, and pcap checks on the target architecture.
- Catalog, checksum, README, source assurance, local build, and independent
  evidence records are complete without changing x86-64 tcpdump.
