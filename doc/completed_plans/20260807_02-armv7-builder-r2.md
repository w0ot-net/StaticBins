# Plan: Expand the ARMv7 Builder for Utility Recipes

*Distilled: 2026-08-07*

## Summary

Publish a second immutable ARMv7 Alpine 3.24.1 builder containing the smallest
package set required by the repository's six current utility profiles. Extend
the existing ARMv7 candidate checks to prove those commands, static archives,
and ARM hard-float links before adopting the published digest. This plan adds
no recipe or distributed executable.

## Problem

`builders/armv7/` currently proves only a minimal C/C++ toolchain with
`build-base` and `file`. GDB, GDBserver, lsof, socat, strace, and tcpdump need
additional configure tools, headers, and static libraries, and ordinary
recipes may not install packages or fall back to mutable package resolution.

## Scope

In scope:

- Resolve exact ARMv7 package versions from the pinned Alpine 3.24.1 base for
  the commands and static inputs used by the six existing feature profiles.
- Publish a non-replaceable `armv7-alpine-3.24.1-r2` builder and adopt its
  verified public digest in `builders/armv7/environment.lock`.
- Validate runtime `armv7l`, OCI `arm`/`v7`, all direct package versions,
  required commands and archives, and executable static C/C++ and library
  probes as ELF32 little-endian ARM hard-float files.
- Update the root builder tag documented for users.

Out of scope:

- Adding recipe directories, catalog rows, artifacts, checksums, or trust
  records.
- Copying AArch64-only convenience packages that no ARMv7 recipe consumes.
- Changing the AArch64 or x86-64 builders or generalizing builder definitions
  or the architecture-generic local publisher.

## Design

Keep the existing `builders/armv7/` ownership and publication lifecycle. Build
the direct package set from observed recipe requirements rather than blindly
copying `builders/aarch64/packages.lock`. The expected set covers Autoconf,
Automake, Bison, Flex, libtool, Perl and Texinfo where the GNU builds require
them; pkgconf and RPC generation; Linux headers; tar/xz extraction; and the
development/static packages for Expat, GMP, MPFR, ncurses, xz, zlib, zstd,
libtirpc, and LibreSSL. Every retained direct row must have one current recipe
consumer or candidate probe.

Expand `builders/armv7/build.sh` in place. In addition to the current base C
and C++ probes, compile and execute bounded static probes for libtirpc-nokrb,
LibreSSL, Expat, and the GDB library set. Discover compiler-owned archive paths
with the locked compiler, but require every observed archive owner and version
to match the candidate image. Apply the current ARMv7 ELF checks to every
probe: ELF32, little-endian, machine `ARM`, hard-float EABI, the selected
executable type, no interpreter, no `DT_NEEDED`, and successful ARMv7
execution.

Use the local publication command introduced by the prerequisite builder-
publication plan. Change the package lock, candidate validation, and
`BUILDER_TAG` together in the working tree, run the candidate validator, and
publish the new non-existing tag with `./builders/publish.sh armv7`. Inspect and
run the reported digest, then set `BUILDER_IMAGE` to that digest before one
reviewed commit makes the complete r2 definition and lock visible on `main`.
Do not expose an incomplete lock or add a mutable-tag/old-builder fallback.

## Affected Components

- `builders/armv7/packages.lock`: record the minimal exact direct package set.
- `builders/armv7/environment.lock`: advance the versioned tag and adopt the
  verified immutable builder digest after publication.
- `builders/armv7/build.sh`: validate the recipe-required commands, archives,
  static library probes, and existing ARMv7/OCI invariants.
- `README.md`: replace the published ARMv7 r1 tag with the adopted r2 tag.

## Implementation Sequence

1. Require the local-validation/trust and local-builder-publication plans to be
   complete.
2. Inventory the commands, headers, and linked static archives used by the six
   existing recipes and resolve only their direct ARMv7 packages against the
   pinned Alpine child manifest.
3. Update the package lock and candidate checks under the new r2 tag. Run the
   local ARMv7 candidate once, retaining BuildKit cache and all diagnostics for
   any late validation correction.
4. Run `./builders/publish.sh armv7`; require it to validate the candidate,
   refuse tag replacement, publish through Buildx, and report one digest.
5. Inspect the published platform, labels, packages, SBOM, provenance, tags,
   runtime, archives, and static probes through an anonymous digest-pinned
   pull.
6. Put the verified digest in `environment.lock`, update the README tag, run
   focused and root validation, then commit and push the complete builder
   definition and adoption together.

## Validation

- Run `bash -n builders/armv7/build.sh` and `git diff --check`.
- Run `./builders/armv7/build.sh`; require all package, command, archive,
  static-link, execution, ELF32, endianness, hard-float, OCI variant, and label
  checks to pass.
- Run `./builders/publish.sh armv7` once for the new r2 tag; inspect the
  reported digest and both ARMv7 tags anonymously, then repeat the candidate
  package and probe checks against that digest.
- Run `./validate.sh`; the catalog and artifact tree must remain unchanged.
- After pushing, anonymously resolve the locked digest again and require the
  same platform and runtime checks without invoking a hosted runner.

## Success Criteria

- `builders/armv7/environment.lock` consumes one published, immutable r2
  `linux/arm/v7` builder with no fallback.
- The builder contains and validates exactly the shared inputs needed by the
  six planned ARMv7 recipes, including executable hard-float static probes.
- No recipe, artifact, checksum, trust status, or other architecture's builder
  changes in this plan.
