# Plan: Add the x86 lsof Recipe and Binary

*Distilled: 2026-08-07*

## Summary

Add lsof 4.99.5 as a reproducible static 32-bit x86 executable. Port the
existing recipe and procfs smoke test to the documented i686/CMOV/SSE2 baseline
using the immutable full-suite x86 builder.

Execute this plan after `20260807_14-x86-tcpdump.md` establishes the x86
artifact and contributor contracts.

## Problem

lsof is available on the three existing architectures but not on the planned
`x86` target. The x86 builder supplies the same no-Kerberos libtirpc interface,
but there is no x86 recipe owner, artifact, or linked-input evidence.

## Scope

In scope:

- Add `recipes/lsof/x86/` with the exact lsof 4.99.5 source, checksum-only
  record, licenses, x86 archive inventory, and focused procfs test.
- Compile for the explicit i686/CMOV/SSE2 baseline and enforce the complete
  static x86 ELF contract.
- Add `artifacts/x86/lsof` and its catalog, manifest, README, and TRUST records.

Out of scope:

- Changing lsof's version, libtirpc policy, feature profile, or existing
  architecture recipes.
- Adding SELinux support, shared liblsof, or stronger source authentication
  that upstream evidence does not currently provide.
- Changing or republishing the x86 builder.

## Design

Port `recipes/lsof/x86_64/` directly and cross-check architecture-independent
files against the ARMv7 owner. Preserve the tracked archive, source lock,
license texts, `--with-libtirpc` and static-only configure policy, link map,
complete archive reconciliation, version check, and procfs smoke behavior.
Adapt only paths, compiler triplet, `linux/386`/binfmt boundary, baseline flags,
archive ownership, and ELF assertions.

Require a stripped ELF32 little-endian `Intel 80386` `ET_EXEC`, compiled with
`-march=i686 -msse2 -mfpmath=sse`, with no interpreter or `DT_NEEDED`. Run the
existing target-container smoke test against a real process and require lsof to
report its PID and open descriptor before installing the candidate.

## Affected Components

- `recipes/lsof/x86/`: add the complete x86 recipe and evidence.
- `artifacts/x86/lsof`: add the validated executable.
- `recipes/catalog.tsv`: enable `(lsof, x86)`.
- `artifacts/SHA256SUMS`: add the sorted exact digest.
- `README.md`: add x86 lsof availability and rebuild support.
- `TRUST.md`: add source and passed recipe-validation facts plus `None` for
  independent evidence.

## Implementation Sequence

1. Require the committed x86 builder and snapshot current lsof inputs and
   artifacts.
2. Copy the nearest recipe, adapt only target constants and inventory, and run
   syntax plus offline source validation.
3. Run `./build.sh lsof x86` once and retain cache for late validation fixes.
4. Add the artifact and shared records only after link, ELF, version, and
   procfs checks pass; validate, commit, and push explicit paths.

## Validation

- Byte-compare architecture-independent source and license inputs with an
  existing lsof owner; run shell syntax, `git diff --check`, and `./validate.sh`.
- Run `./build.sh lsof x86` once; require exact source checksum, complete link
  inventory, exact version, and the process/descriptor procfs assertions.
- Inspect the candidate and installed file with `file`, `readelf`, and
  `sha256sum`; require the explicit CPU flags in the recorded build, ELF32
  little-endian x86 `ET_EXEC`, stripping, no interpreter, no `DT_NEEDED`, and
  candidate/install byte equality.

## Success Criteria

- `./build.sh lsof x86` recreates the committed artifact from tracked inputs
  and the immutable x86 builder.
- The x86 binary passes the same link, version, and procfs behavior contract as
  existing lsof artifacts.
- Existing lsof bytes and assurance records remain unchanged.
