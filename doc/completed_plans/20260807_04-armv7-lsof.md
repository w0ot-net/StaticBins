# Plan: Add the ARMv7 lsof Recipe and Binary

*Distilled: 2026-08-07*

## Summary

Add lsof 4.99.5 as a reproducible static ARMv7 executable with the repository's
existing Linux, RPC, and procfs feature profile. Port the current AArch64 recipe
directly, retaining its controlled open-file smoke test and complete linked
archive evidence.

## Problem

lsof is available for AArch64 and x86-64 but has no ARMv7 recipe or artifact.
The generic dispatcher already accepts ARMv7, so the missing work belongs
entirely to the tool-owned recipe and distribution records.

## Scope

In scope:

- Add one `recipes/lsof/armv7/` owner with the existing lsof 4.99.5 source,
  checksum-only authentication declaration, feature policy, licenses, and
  target procfs smoke test.
- Produce and commit a stripped static `artifacts/armv7/lsof` with catalog,
  checksum, README, and TRUST records.
- Validate libtirpc linkage and ARMv7 ELF class, endianness, machine, and
  hard-float ABI in both guest and host checks.

Out of scope:

- Changing lsof's version, enabling SELinux or the separate liblsof output, or
  adding setuid/setgid installation modes.
- Sharing recipe scripts across architectures or modifying existing lsof
  artifact bytes.
- Adding an independent rebuild service or provenance attestation.

## Design

Reuse the AArch64 recipe's configure switches, `libtirpc-nokrb` static link,
link-map inventory, unrestricted listing policy, and controlled procfs test.
Copy the exact tracked archive and reviewed licenses into the conventional
ARMv7 directory, retaining the explicit `checksum-only` assurance level.

Translate the platform, builder lock, output path, compiler triplet, and exact
compiler-owned archive paths to ARMv7. Extend both validation layers to require
ELF32 little-endian ARM, hard-float EABI, `ET_EXEC`, static linkage, stripping,
and no interpreter or `DT_NEEDED`. The existing smoke test must find the exact
uniquely named file held open by its controlled target under ARMv7 procfs.

Use existing generic catalog and validation behavior without new abstractions
or tests. Record the maintainer-built recipe validation and the absence of an
independent rebuild as separate facts; do not claim that the checksum proves
build provenance.

## Affected Components

- `recipes/lsof/armv7/*`: add the complete ARMv7 recipe, tracked source,
  licenses, inventory, and smoke test.
- `artifacts/armv7/lsof`: add the validated executable.
- `recipes/catalog.tsv`: enable the `lsof, armv7` pair.
- `artifacts/SHA256SUMS`: add its sorted exact digest.
- `README.md`: list the ARMv7 binary and rebuild path.
- `TRUST.md`: record checksum-only source assurance, the local recipe build,
  and that no independent rebuild evidence is recorded.

## Implementation Sequence

1. Start after the ARMv7 r2 builder is adopted.
2. Port the AArch64 recipe and replace every architecture-bound value and
   archive-inventory path with values verified inside the ARMv7 builder.
3. Announce a rough runtime if the emulated build is expected to exceed ten
   minutes, then run the direct ARMv7 build once and retain its BuildKit cache.
4. Add the catalog, manifest, README, and TRUST records only after the target
   functional test passes; stage explicit paths, validate, commit, and push.

## Validation

- Run `./validate.sh` and `git diff --check`.
- Run `./build.sh lsof armv7`; require exact version/features, complete link
  inventory, and successful controlled procfs discovery.
- Inspect the candidate and installed file with `file` and `readelf` for all
  ARMv7/static/stripping invariants and verify its manifest digest.
- Confirm the committed recipe and artifact still pass local validation after
  the push without rebuilding unrelated artifacts.

## Success Criteria

- `./build.sh lsof armv7` deterministically rebuilds the committed executable
  from tracked inputs and the immutable builder.
- The executable is a stripped static ARMv7 hard-float `ET_EXEC`, exposes the
  documented feature profile, and passes the procfs test.
- All distribution and assurance records are complete, with existing lsof
  recipes and artifacts unchanged.
