# Plan: Add the ARMv7 GDB Recipe and Binary

*Distilled: 2026-08-07*

## Summary

Add GNU GDB 17.2 as a reproducible static ARMv7 executable with the existing
reduced feature profile. Retain the AArch64 recipe's authenticated source and
complete static-link evidence, and add a focused batch test that loads and
inspects a known ARMv7 executable without depending on ptrace.

## Problem

The full GDB client is distributed only for AArch64. ARMv7 has a capable
builder boundary but lacks a tool-owned recipe, artifact, source/license
records, and functional validation beyond the generic builder probes.

## Scope

In scope:

- Add `recipes/gdb/armv7/` with the exact GNU-signed GDB 17.2 source, current
  curses/Expat/compression profile, linked archive inventory, licenses, and a
  focused batch-mode target inspection test.
- Build and commit `artifacts/armv7/gdb` and its catalog, checksum, README, and
  TRUST records.
- Enforce static ARMv7 hard-float ELF and stripping invariants at guest and
  host boundaries.

Out of scope:

- Enabling Python, Guile, debuginfod, source-highlight, Babeltrace, Intel PT,
  simulators, or bundled binutils tools, or updating GDB.
- Requiring ptrace/local inferior execution when a deterministic file/symbol
  inspection test covers the static runtime and BFD path without another VM.
- Refactoring the AArch64 recipe or adding an independent rebuild service or
  provenance attestation.

## Design

Port the AArch64 recipe directly, preserving its source authentication,
configure switches, GNU libtool `-all-static` final link, link-map inventory,
and reviewed notices. Copy the existing tracked archive/signature/keyring bytes
into the ARMv7 owner and verify them offline.

Use the locked ARMv7 compiler triplet and exact compiler-owned archive paths.
Make the executable type explicit with the compiler/libtool's supported
non-PIE static-link option and require a stripped static `ET_EXEC`; do not
accept whichever type the toolchain default happens to emit. If a bounded
evidence build cannot produce that profile without Makefile rewriting, stop
and revise the plan. In addition to no interpreter and no `DT_NEEDED`, require
ELF32, little-endian ARM, and hard-float EABI flags in guest and host
validation.

Add a tiny static ARMv7 smoke target as a Docker build output and run GDB in
the target container with `--batch --nx`. Do not strip this test-only target:
retain its ordinary symbol table and a non-optimized known data symbol so the
commands can load the file, report the expected ARM architecture, resolve the
symbol, and evaluate its value. The distributed GDB candidate remains stripped.
This catches BFD/symbol-reading and static runtime failures while avoiding the
known ptrace limitations of user-mode emulation.
Record the maintainer-built recipe validation separately from the absence of
independent rebuild evidence.

## Affected Components

- `recipes/gdb/armv7/*`: add authenticated source inputs, build scripts,
  focused smoke target/test, license texts, and final-link inventory.
- `artifacts/armv7/gdb`: add the validated executable.
- `recipes/catalog.tsv`: enable the ARMv7 GDB pair.
- `artifacts/SHA256SUMS`: add its sorted exact checksum.
- `README.md`: list ARMv7 GDB and its rebuild path.
- `TRUST.md`: add GNU PGP source assurance, the local recipe build record, and
  the absence of independent rebuild evidence.

## Implementation Sequence

1. Require the expanded ARMv7 builder and verify every GDB static dependency
   and compiler-owned path inside its immutable digest.
2. Port the source, licenses, scripts, inventory, and smoke target; run offline
   PGP and syntax checks before the expensive build.
3. Tell the user the expected emulated compile duration. Build once with a
   retained cache, reconcile every linked archive, and run version plus focused
   batch target inspection before installing the candidate.
4. Add catalog/manifest/live records, stage only explicit paths, validate,
   commit, and push.

## Validation

- Run offline PGP validation for the exact GNU fingerprint, C warning checks,
  `./validate.sh`, and `git diff --check`.
- Run `./build.sh gdb armv7`; require the static link inventory, exact version,
  and deterministic batch-mode architecture/symbol/data assertions.
- Inspect the candidate, smoke target, and installed artifact with `file` and
  `readelf`, including ELF32, endianness, ARM hard-float, static `ET_EXEC`, and
  absence of interpreter/needed entries. Require the GDB candidate and installed
  artifact to be stripped, while the test-only target retains the symbol used by
  the batch assertions.
- Verify the installed checksum and complete manifest, then rerun
  `./validate.sh` without adding an independent rebuild or attestation claim.

## Success Criteria

- The committed GDB is a stripped static ARMv7 hard-float `ET_EXEC` built from
  authenticated tracked source and fully inventoried static inputs.
- The focused target-architecture test proves version, BFD target loading,
  architecture reporting, symbol resolution, and data evaluation.
- Existing GDB bytes and feature policy remain unchanged.
