# Plan: Add the ARMv7 socat Recipe and Binary

*Distilled: 2026-08-07*

## Summary

Add socat 1.8.1.3 as a reproducible static ARMv7 executable with LibreSSL TLS,
SCTP, and the existing relay feature profile. Port the proven AArch64 recipe
and retain its bounded TCP, Unix-socket, and TLS functional tests.

## Problem

socat is distributed for AArch64 and x86-64, but ARMv7 users have neither a
committed binary nor a recipe that consumes the published ARMv7 builder.

## Scope

In scope:

- Add `recipes/socat/armv7/` with the exact deterministic upstream archive,
  checksum-only source declaration, existing configure policy, license texts,
  and final-link inventory.
- Build and commit `artifacts/armv7/socat` plus the required catalog, checksum,
  README, and TRUST records.
- Validate the promised feature macros, three relay modes, complete static
  LibreSSL link, and ARMv7 hard-float ELF contract.

Out of scope:

- Updating socat or LibreSSL, enabling readline, libwrap, or FIPS, or changing
  existing architecture artifacts.
- Extracting shared smoke-test or recipe abstractions.
- Adding an independent rebuild service or provenance attestation.

## Design

Reuse the current `SOURCE_DATE_EPOCH`, configure switches, link-map parsing,
license inventory, and smoke test. Copy the exact tracked archive and reviewed
license material into the ARMv7 owner; do not regenerate the Git archive or
substitute a new upstream download.

Bind the host script to `linux/arm/v7`, the ARMv7 environment lock, `arm`
binfmt registration, and `artifacts/armv7/socat`. Verify the locked ARMv7
compiler triplet and GCC archive paths rather than assuming AArch64 spellings.
Both guest and host checks must require ELF32, little-endian ARM, hard-float
EABI, static `ET_EXEC`, stripping, and no interpreter or `DT_NEEDED`.

Run the existing target smoke test without public networking: exact version
and macros, bounded loopback TCP relay, Unix-socket relay, and ephemeral
LibreSSL TLS relay. Record the maintainer-built recipe validation separately
from the absence of independent rebuild evidence.

## Affected Components

- `recipes/socat/armv7/*`: add the ARMv7 build, source, license/link evidence,
  and functional smoke test.
- `artifacts/armv7/socat`: add the validated executable.
- `recipes/catalog.tsv`: enable `socat, armv7`.
- `artifacts/SHA256SUMS`: add the sorted artifact checksum.
- `README.md`: list the ARMv7 binary and rebuild command.
- `TRUST.md`: add checksum-only source, local recipe build, and independent
  evidence records.

## Implementation Sequence

1. Require the adopted ARMv7 r2 builder.
2. Port and inspect the recipe inputs, then establish the exact ARMv7
   compiler-owned archive rows from one evidence link.
3. Announce a rough estimate before any build expected to exceed ten minutes;
   build once, preserve cache, and correct late inventory or smoke assertions
   without recompiling when possible.
4. Add and stage the shared catalog/manifest/live-document records only after
   the target smoke test passes, then validate, commit, and push.

## Validation

- Run `./validate.sh` and `git diff --check`.
- Run `./build.sh socat armv7`; require exact feature output, complete linked
  archive evidence, and successful TCP, Unix, and TLS relays.
- Reinspect candidate and installed bytes with `file`, `readelf`, and
  `sha256sum`, including ARM hard-float flags and manifest completeness.
- Confirm the committed recipe and artifact still pass local validation after
  the push.

## Success Criteria

- The committed socat is a stripped static ARMv7 hard-float `ET_EXEC` with the
  documented TLS/SCTP profile and functional relay coverage.
- A fresh checkout rebuilds it from tracked source bytes and the immutable
  ARMv7 builder through the standard dispatcher.
- Existing socat artifacts and feature profiles remain unchanged.
