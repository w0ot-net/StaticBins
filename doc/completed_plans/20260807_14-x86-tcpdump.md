# Plan: Activate x86 with a tcpdump Recipe and Binary

*Distilled: 2026-08-07*

## Summary

Add tcpdump 4.99.4 with libpcap 1.10.4 as the first reproducible static `x86`
artifact. Port the proven x86-64 recipe and deterministic offline packet test
to the locked `linux/386` builder, then activate the first x86 recipe and
artifact in the distribution, ABI contracts, and user documentation. This plan
establishes real tool coverage without porting every utility at once.

Execute this plan only after `20260807_13-x86-builder.md` has published,
verified, committed, and pushed the immutable x86 builder digest.

## Problem

The builder-foundation plan registers x86 for generic dispatch, validation, and
publication but deliberately adds no recipe or distributed executable. The
architecture documents do not yet promise the artifact ABI, and no committed
binary proves that a normal recipe can build and run on the target.

tcpdump is the smallest mature architecture port that closes that gap. Its
current x86-64 recipe has authenticated tracked sources, a bounded static link,
and a deterministic smoke test covering version reporting, BPF compilation,
and offline packet decoding without privileged capture or target-kernel
debugging behavior.

## Scope

In scope:

- Add `x86` as the repository identifier for 32-bit little-endian Linux x86
  using Alpine's i686-compatible CMOV/SSE2 baseline and OCI `linux/386` only at
  container boundaries.
- Add one complete `recipes/tcpdump/x86/` recipe using the committed x86
  builder digest and exact copies of the reviewed tcpdump/libpcap inputs and
  authentication evidence.
- Build, strip, smoke-test, and distribute `artifacts/x86/tcpdump` as an ELF32
  static executable with the existing tcpdump feature profile.
- Add the enabled catalog row, complete checksum manifest entry, and factual
  source/build/independent-evidence records.
- Update the nearest owning artifact, agent, and user documents for the proven
  x86 ABI and first distributed utility.

Out of scope:

- Adding x86 GDB, GDBserver, lsof, socat, strace, or any other x86 artifact;
  each remains an independently executable following plan.
- Expanding or republishing the x86 builder unless the tcpdump build proves a
  required input was omitted; if so, stop and revise the prerequisite builder
  plan rather than resolving packages inside the recipe.
- Changing the x86-64 tcpdump recipe, artifact bytes, historical attestation,
  trust status, feature profile, or builder.
- Supporting CPUs below the documented CMOV/SSE2 baseline, x32, or dynamic
  linking.
- Claiming an exact rebuild or provenance attestation for the new artifact
  before an independent qualifying build actually reproduces it.

## Design

Keep `x86` as the only internal name. Translate it to Alpine `x86`, OCI
architecture `386`, Docker platform `linux/386`, binfmt target `386`, and the
compiler's actual Alpine target triplet only inside builder and recipe scripts.
The artifact promise is a stripped ELF32 little-endian `ET_EXEC` whose ELF
machine is `Intel 80386`, compiled for the documented i686/CMOV/SSE2 baseline,
with no program interpreter or `DT_NEEDED` entries. Because ELF `e_machine`
cannot distinguish i386 from i686, use
`CFLAGS="-O2 -pipe -march=i686 -msse2 -mfpmath=sse"` for both libpcap and
tcpdump in the pinned Alpine x86 environment rather than inferring the CPU
generation from `readelf` alone.

Port `recipes/tcpdump/x86_64/` directly rather than introduce shared scripts or
symlinks. Retain tcpdump 4.99.4, libpcap 1.10.4, their official HTTPS URLs,
checksums, PGP signatures, minimal keyring, full signer fingerprint, license
texts, feature omissions, and deterministic smoke fixture. Store exact regular
mode-`100644` copies under `recipes/tcpdump/x86/sources/`; the existing
validator requires recipe-owned tracked inputs and verifies their bytes and
signatures offline.

Adapt only architecture-specific behavior: paths, platform, emulation target,
compiler baseline, target triplet/archive inventory, ELF checks, and messages.
Discover compiler-owned archive paths with the locked compiler, reconcile the
final link map against a reviewed x86-specific inventory, and record the exact
package versions, licenses, and source evidence observed in the final link.
Do not inherit x86-64 archive paths or assume that static linking alone proves
the output architecture.

Use the existing Buildx-only host flow. Require Buildx before emulation,
pulling the locked builder, or creating temporary output. Try native
`linux/386` execution, install only pinned `386` binfmt support when necessary,
pull the exact builder digest, and export a temporary candidate. Run the
existing version/BPF/offline-decode smoke test through `linux/386`, validate the
candidate completely, install it at mode `0755`, then repeat ELF and SHA-256
checks before reporting the result.

Activate the first utility only with the complete artifact change. The builder
catalog already makes `x86` available to generic dispatch and validation, so do
not modify `build.sh`, `scripts/recipes.py`, `builders/publish.sh`, or their
focused architecture-catalog tests. Prove the real catalog row derives the
conventional recipe, builder, and artifact paths through normal validation and
dispatch while boundary spellings such as `386`, `i386`, `i686`, and `amd64`
remain absent.

Record the new artifact in `TRUST.md` with `Committed recipe and target checks
passed` for build validation and `None` for independent evidence. The x86-64
tcpdump exact rebuild and historical attestation remain scoped only to the
x86-64 bytes and must not be copied to this artifact.

## Affected Components

- `recipes/tcpdump/x86/`: own the x86 build, tracked authenticated inputs,
  license/link evidence, deterministic smoke test, and user instructions.
- `artifacts/x86/tcpdump`: add the validated executable.
- `recipes/catalog.tsv`: add the enabled `(tcpdump, x86)` identity.
- `artifacts/SHA256SUMS`: add the exact sorted digest record.
- `TRUST.md`: add x86 source and artifact records without borrowing x86-64
  independent evidence.
- `README.md`: add the ready-to-run x86 tcpdump row and one-command rebuild.
- `doc/architecture/artifacts/ARTIFACT_CONTRACT.md`: define the x86 ELF32,
  endianness, machine, and CPU-baseline checks.
- `AGENTS.md`: require explicit x86 ELF32, little-endian, and CPU-baseline
  validation for this supported identifier.

## Implementation Sequence

1. Require the committed `builders/x86/environment.lock` to contain the
   anonymously verified digest from the prerequisite plan. Snapshot the
   x86-64 tcpdump artifact hash so this work can prove it remains unchanged.
2. Copy the x86-64 tcpdump recipe into the conventional x86 owner, then make
   only the architecture-specific path, platform, exact compiler-baseline,
   archive-inventory, validation, and documentation changes. Keep all accepted
   source and PGP evidence bytes exact.
3. Run syntax and current-catalog validation, then byte-compare the copied
   `source.lock`, `smoke-test.sh`, reviewed license texts, and every archive,
   detached signature, and keyring under `sources/` with the x86-64 owner before
   the expensive build. Build once through `./recipes/tcpdump/x86/build.sh`,
   retain BuildKit cache for any late validation correction, and require the
   complete static ELF and deterministic target smoke test to pass before
   installation.
4. Add the recipe catalog row, artifact checksum, trust records, README row,
   and nearest authoritative artifact/agent contract updates as one activation
   change.
5. Run focused validation and `./validate.sh`; confirm only the new x86
   artifact and its records changed, then commit and push explicitly staged
   paths.

## Validation

- Run `bash -n build.sh recipes/tcpdump/x86/build.sh`,
  `sh -n recipes/tcpdump/x86/build-in-container.sh recipes/tcpdump/x86/smoke-test.sh`,
  and `git diff --check`.
- Inspect the committed builder-catalog row and require normal validation to
  derive `recipes/tcpdump/x86`, `builders/x86/environment.lock`, and
  `artifacts/x86/tcpdump`; require `./build.sh list` to expose only the internal
  `x86` spelling for the new pair.
- Before the build, run `python3 scripts/recipes.py validate` on the current
  catalog and use `cmp` to require that the x86 `source.lock`, `smoke-test.sh`,
  reviewed license texts, archives, detached signatures, and keyring are
  byte-identical to the validated x86-64 inputs. The architecture-owned
  `README.md`, `licenses/NOTICE.md`, and `licenses/archive-inventory.tsv` are the
  deliberate adaptations. After adding the x86 catalog row and artifact, run
  the validator again and require both tcpdump and libpcap inputs and PGP
  evidence to validate under the new recipe owner.
- Run `./recipes/tcpdump/x86/build.sh` once. Require the locked builder digest,
  final-link inventory, stripping, the literal
  `-march=i686 -msse2 -mfpmath=sse` baseline, ELF32, little-endian data, `Intel
  80386` machine, `ET_EXEC`, no interpreter, no `DT_NEEDED`, exact
  tcpdump/libpcap versions, BPF compilation, deterministic packet decode, and
  successful `linux/386` execution.
- Run `file`, `readelf`, and `sha256sum` against the installed
  `artifacts/x86/tcpdump`; mount that installed file into the pinned Alpine image
  for the committed smoke test under `linux/386`, and require its bytes to equal
  the validated candidate.
- Run `./validate.sh` and `./build.sh list`. Confirm the new enabled pair appears
  once, `artifacts/SHA256SUMS` is complete and sorted, the new file has Git mode
  `100755`, and the pre-change x86-64 tcpdump hash is unchanged.

## Success Criteria

- `./build.sh tcpdump x86` reproducibly creates or replaces exactly
  `artifacts/x86/tcpdump` from committed inputs and the immutable x86 builder.
- The committed artifact is a stripped static ELF32 little-endian x86
  executable for the documented i686/CMOV/SSE2 baseline and passes the focused
  target smoke test.
- Recipe catalog, checksum, trust, README, agent, and artifact records
  consistently expose `x86` without accepting OCI/compiler spellings as
  repository identifiers.
- Existing artifacts, recipes, builders, and historical independent evidence
  remain unchanged; the other x86 utilities remain separate planned work.
