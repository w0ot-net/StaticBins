# Plan: Add Standalone netstat Across Ready Architectures

## Summary

Add only the standalone `netstat` program from net-tools 2.10 for `aarch64`,
`armv7`, `x86`, and `x86_64`. Use a tracked noninteractive feature
configuration and one reviewed modern-libc correctness patch, validate Linux
procfs behavior on each target, and keep the rollout independent of BusyBox.

## Problem

The repository lacks the familiar `netstat` interface for inspecting sockets,
routes, interfaces, and protocol statistics. BusyBox has a smaller netstat
applet, but it does not provide the full net-tools behavior users generally
mean by the standalone command.

The net-tools 2.10 build system defaults to an interactive Bash configuration
and enables many obsolete protocol families. Its released source also uses the
nonstandard `%Lu` scanf length in interface-counter parsing, a correctness bug
that current Alpine packaging patches. A repeatable recipe must avoid prompts,
choose a bounded modern Linux feature set, and carry the necessary patch with
explicit provenance.

## Scope

In scope:

- Add net-tools 2.10 `netstat` as `artifacts/<architecture>/netstat` for all
  four ready architectures.
- Enable Unix sockets, IPv4, IPv6, Ethernet/loopback interface reporting,
  routes, and protocol statistics; disable I18N, SELinux, masquerade reporting,
  and legacy non-IP address/hardware families.
- Track and checksum the Alpine-carried patch that restores standard `%llu`
  parsing for `unsigned long long` interface counters.
- Build only `netstat`, validate a classic static `ET_EXEC`, and functionally
  test controlled TCP-listener discovery plus route, interface, Unix-socket,
  and protocol-statistics reads from procfs.
- Document that net-tools itself calls this program mostly obsolete and points
  users to `ss`/`ip` for newer interfaces.

Out of scope:

- Other net-tools programs such as `ifconfig`, `route`, `arp`, `hostname`,
  `mii-tool`, `iptunnel`, or `slattach`.
- BusyBox netstat, iproute2, `ss`, non-Linux ports, legacy IPX/AppleTalk/
  AX.25/NET-ROM/ROSE/X.25 families, or SELinux integration.
- Editing upstream Makefiles to remove programs or creating a generic
  repository configuration framework.
- Builder changes, root README changes, or architecture-contract changes.

## Design

Use the official SourceForge HTTPS `net-tools-2.10.tar.xz` release archive with
accepted SHA-256
`b262435a5241e89bfa51c3cabd5133753952f7a7b7b93f32e08cb9d96f580d69`.
Declare `checksum-only`: the release directory does not publish a detached
signature over the tarball that the recipe can verify with an authenticated
full-fingerprint key. The signed mailing-list announcement identifies the
release but is not a substitute for a signature over the accepted bytes.

Track
`0001-Revert-sscanf-pattern-is-Lu-not-llu-for-long-long-un.patch` from Alpine
aports at SHA-256
`6d276b0f302a72a92229f211d4cc4a54ec6f8a44006f5453f6970ba361eae165`.
Record both Alpine's immutable source URL and its `Patch-Source` link to the
upstream net-tools discussion. Apply it with exact context and verify the hash
before use. The patch remains checksum-only reviewed downstream evidence and
must not be described as an authenticated upstream release input.

Do not invoke upstream's interactive `configure.sh`, which requires Bash and
would silently accept defaults. Commit a recipe-owned `netstat.config.make`
that explicitly sets only `HAVE_AFUNIX`, `HAVE_AFINET`, `HAVE_AFINET6`, and the
minimal Ethernet/loopback support needed by the promised interface. Generate
`config.h` deterministically from that file using the same macro mapping used
by established Alpine packaging, and check the generated definitions before
compilation. All other families and optional programs remain disabled.

Invoke the upstream `netstat` target directly, not `all` or `install`. Use
`-O2 -pipe`, add `-march=i686 -msse2 -mfpmath=sse` on x86, and link with
`-static` plus a linker map, without `-no-pie`. Select and enforce classic
static `ET_EXEC`; stop if the locked toolchain cannot produce it. The internal
`libnet-tools.a` is source-built from the same authenticated archive and must
be represented in the final-link inventory separately from builder-owned
musl/libgcc archives.

Retain the upstream GPL-2.0-or-later text and copyright notices. The link
validator resolves every archive from the map, verifies builder-package owners
where applicable, and treats the source-built net-tools archive as covered by
the locked release source and its license. No disabled net-tools executables
are exported or installed.

The target smoke test checks exact `netstat --version` output, starts a
controlled BusyBox TCP listener on numeric loopback in an isolated target
container, and requires `netstat -lnt` to report its exact port and LISTEN
state. It also requires `netstat -rn`, `netstat -i`, `netstat -xan`, and
`netstat -s` to parse the target's real `/proc` data and emit their expected
headers, including the loopback interface. Use numeric modes to avoid DNS or
services-file dependencies and bound the listener with explicit cleanup and
timeouts.

Host scripts follow the normal Buildx-only candidate flow, perform prerequisites
before emulation or pulls, use the exact builder digest, repeat all architecture
and ELF checks before and after installation, and require installed bytes to
match the smoke-tested candidate.

## Affected Components

- `recipes/netstat/{aarch64,armv7,x86,x86_64}/`: add Dockerfiles, host/guest
  build scripts, smoke tests, READMEs, source locks and archives, the tracked
  scanf patch, noninteractive feature configs, and license/link inventories.
- `recipes/catalog.tsv`: add four enabled `netstat` rows.
- `artifacts/{aarch64,armv7,x86,x86_64}/netstat`: add the four stripped static
  executables.
- `artifacts/SHA256SUMS`: add sorted exact checksums for the four artifacts.
- `TRUST.md`: add four checksum-only net-tools source records, the absence of a
  detached release-file signature, and no independent artifact evidence unless
  one is actually obtained.

## Implementation Sequence

1. Fetch the official archive and the immutable Alpine patch into temporary
   storage; verify their exact checksums, sizes, provenance links, applicable
   GPL terms, and patch contents before copying mode-100644 inputs to each
   architecture recipe.
2. Implement the x86-64 recipe with the explicit config files, exact patch
   application, `netstat`-only build, source/builder archive inventory, ELF
   checks, and procfs smoke test; run syntax checks and one real build first.
3. Replicate the proven recipe to AArch64, ARMv7, and x86, changing only
   platform, target/ABI checks, triplets, and the required x86 CPU flags. Keep
   source, patch, feature macros, and functional coverage identical.
4. Warn that the remaining emulated builds and target tests may exceed ten
   minutes and provide an estimate, then build all remaining architectures
   through their committed builder digests.
5. Add all four catalog entries together, update the complete checksum manifest
   and trust records, confirm final binary sizes are acceptable, and audit that
   no other net-tools executable entered the output or tracked tree.
6. Run focused and full repository validation, then commit and push only the
   complete netstat rollout and completed-plan record.

## Validation

- Run `bash -n` on host scripts, `sh -n` on guest/smoke scripts,
  `git diff --check`, and direct checks that the tracked config declares the
  intended enabled and disabled macros without duplicates.
- Verify every source archive and patch checksum before extraction/application;
  require `checksum-only` reporting and no PGP fallback behavior.
- Build only the `netstat` target and inspect the linker map. Require every
  source-built or package-owned archive to have version, license, source, and
  reviewed license-file evidence.
- For candidates and installed artifacts, require the exact machine, ELF class,
  endianness, ABI, stripped state, classic `ET_EXEC`, no `PT_INTERP`, and no
  `DT_NEEDED`; require ARMv7 hard-float and x86 i686/CMOV/SSE2 details.
- On each target architecture, verify version 2.10, detect a controlled numeric
  TCP listener with `-lnt`, and successfully parse numeric route, loopback
  interface, Unix-socket, and protocol-statistics views from `/proc`.
- Require candidate/installed hash equality, run
  `sha256sum -c artifacts/SHA256SUMS`, and run `./validate.sh`.
- Confirm four enabled netstat rows and four artifacts exist and no BusyBox,
  other net-tools output, builder, generic validator, root README, or
  architecture-policy file changed.

## Success Criteria

- `./build.sh netstat <architecture>` works from a fresh checkout for all ready
  architectures using only tracked inputs and the locked builders.
- Every committed netstat is a stripped static `ET_EXEC` for its promised host
  and correctly reports controlled sockets plus core Linux procfs views.
- The feature set is explicit, noninteractive, and limited to modern Unix/IPv4/
  IPv6 Linux use; legacy families and other net-tools programs are absent.
- The released source, required scanf patch, source-built library, builder
  archives, GPL notices, checksums, and trust limitations are completely
  recorded and validated.
- Documentation identifies net-tools 2.10 and its upstream-obsolete status
  without coupling the artifact to BusyBox or expanding repository machinery.

## Execution Notes

- Implemented the standalone net-tools 2.10 `netstat` for `aarch64`, `armv7`,
  `x86`, and `x86_64`. Every recipe consumes its committed builder digest,
  verifies the tracked release and immutable Alpine correctness patch, applies
  that patch with zero fuzz, generates `config.h` from the complete reviewed
  44-option noninteractive config, and builds only the upstream `netstat`
  target.
- Added four enabled catalog rows, stripped artifacts, exact SHA-256 manifest
  entries, checksum-only trust records, and per-architecture source, patch,
  linked-input, license, and feature documentation. No BusyBox alias or other
  net-tools executable is distributed.
- Each target smoke test starts a controlled numeric IPv4 listener with the
  locked builder's BusyBox and requires standalone netstat to report it, then
  validates numeric route, loopback-interface, Unix-socket, and protocol-
  statistics views from the target container's real procfs.
- Bounded deviation: the locked Alpine GCC toolchains naturally emit static
  PIE for `-static`, consistent with the current artifact contract. The
  recipes enforce stripped static `ET_DYN` executables with no interpreter,
  `DT_NEEDED`, or text relocations instead of the plan's stale classic
  `ET_EXEC` expectation.
- Bounded correction: command-line `CFLAGS` suppresses net-tools' required
  makefile include-path appends, and the upstream parallel dependency graph can
  enter `lib/` before `version.h` exists. The guest build creates `version.h`
  first and passes target flags through the environment, preserving upstream's
  own appended flags without editing its Makefiles.
- Bounded repository metadata change: the accepted Alpine patch contains
  original email-format whitespace that `git diff --check` diagnoses. A
  recipe-scoped `.gitattributes` rule disables whitespace diagnostics only for
  `recipes/netstat/*/patches/*.patch`, retaining the exact checksum-locked
  bytes rather than rewriting the reviewed downstream input.
- Validation succeeded: syntax checks for every host, guest, smoke, and ELF
  script; exact source and patch checksum checks; config schema and cross-
  architecture identity checks; all four real Buildx builds and target smoke
  tests; `python3 -m unittest tests.test_recipes` (25 tests);
  `git diff --check`; `sha256sum -c artifacts/SHA256SUMS`; and `./validate.sh`
  (40 enabled recipes). ARMv7 additionally passed ELF32, little-endian, EABI5
  hard-float checks, and x86 compile/link logs contain the required i686/SSE2
  baseline.
- Implementation commit: `466c070` (`Add static netstat`).
- No unresolved blocker or deliberately excluded follow-up remains within this
  plan's scope.
